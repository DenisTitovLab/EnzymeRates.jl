EnzymeRates.Fitting.fit_rate_equation — Method
fit_rate_equation(fp::FittingProblem, optimizer;
    n_restarts=20, maxtime=60.0, maxiters=10_000_000,
    abstol=nothing, reltol=nothing, callback=nothing,
    lb=centre .- 15.0, ub=centre .+ 15.0,
    solver_kwargs=(;))

Fit rate constants by minimizing loss! using Optimization.jl.

Runs n_restarts independent optimizations from random initial points and returns the best result. Each start draws every log-space parameter from a normal distribution around its centre, with a standard deviation of 2, and clamps it to the box. The centre comes from the geometric means of the table's nonzero concentrations and of its |Rate|: a binding's K centres on the concentrations it binds, any other rapid-equilibrium K on what the step gives off over what it takes up, a rate constant on the rate over the concentrations it takes up, a regulator's K on its ligand's concentrations and L on 1.

maxtime and maxiters are Optimization.jl common solver options forwarded to every Optimization.solve call. abstol, reltol, and callback are common options forwarded only when set (otherwise each solver uses its own default). solver_kwargs is a NamedTuple of solver-specific options forwarded verbatim to solve (e.g. (; popsize=200) for a CMA-ES solver that supports it). A key present in both a named common option and solver_kwargs takes the solver_kwargs value. lb/ub are the log-space bounds passed to the OptimizationProblem. They hold absolute log values, and by default lie 15 log units either side of each centre, so the box follows the data.

In relative mode (fp.rate_data.absolute == false) the returned steady-state rate constants are multiplied by one factor so the mechanism reproduces the reference turnovers fp.rate_data.reference (see FittingProblem): the geometric mean of measured over predicted turnover. Without a reference the factor is 1 over the largest absolute rate the fit predicts at the data's concentrations, at E_total = 1. A fit whose predicted turnover at a reference anchor is zero, non-finite or of the other sign, or whose largest predicted rate is zero or non-finite, has no such factor: it returns its parameters unscaled, with loss = Inf and retcode = :ReferenceFailed, and does not throw. In absolute mode, or when no restart reaches a finite loss (loss = Inf, retcode = :NoFiniteLoss), the rate constants are returned as fitted.

Returns a NamedTuple (params, loss, retcode, at_bound) where:

  • params: fitted rate constants as a NamedTuple
  • loss: the best loss value achieved
  • retcode: the Symbol form of the best restart's sol.retcode. Only :Success indicates the optimizer converged on its own criteria; any other value (e.g. :MaxTime — hit the time budget; :Failure; :Default — ran but did not flag success) means the fit should be treated as un-converged (check retcode !== :Success); :ReferenceFailed marks a failed reference scale.
  • at_bound: the names of the fitted parameters whose best point lies within 0.01 log units of its lb or ub, read before the relative-mode scale, which can move a reported rate constant outside the box. () when no restart reaches a finite loss. "At bound" does not mean wrong: a parameter no data constrain wanders across the box.

EnzymeRates.identify_rate_equation — Method
identify_rate_equation(prob; optimizer,
    min_beam_width=50, loss_rel_threshold=1.3, loss_abs_threshold=0.001,
    loss_parsimony_threshold=0.99,
    max_param_count=20, eq_complexity_filter=337,
    optional_allosteric_regulators=Symbol[],
    optional_competitive_inhibitors=Symbol[],
    n_restarts=20, maxtime=600.0, maxiters=10_000_000,
    abstol=nothing, reltol=nothing, callback=nothing, solver_kwargs=(;),
    n_cv_candidates=5, se_threshold=1.0,
    save_dir=_default_save_dir(), show_progress=true)

Find the best rate equation for the given reaction and data using beam search.

Keyword Arguments

  • min_beam_width::Int = 50: minimum rate-law keys to expand per param-count tier; a sweep expands every mechanism it meets whose key is selected
  • loss_rel_threshold::Float64 = 1.3: relative tolerance for beam selection (see "Beam selection" below)
  • loss_abs_threshold::Float64 = 0.001: absolute tolerance for beam selection
  • loss_parsimony_threshold::Float64 = 0.99: the loss cutoff admits a key only if its loss is within this factor of the best model of any smaller parameter count — an added parameter must earn its keep. Combined with the other loss thresholds via min; min_beam_width is a cumulative per-count budget (see "Beam selection" below). Inf disables it.
  • max_param_count::Int = 20: skip, before fitting, any mechanism with more fitted constants than this (FittedParameters), so the search stops at this parameter count
  • eq_complexity_filter::Int = 337: skip (before fitting, before any derivation) any mechanism whose rate equation is more complex than this — roughly the number of terms in the rate equation's denominator: V×τ, the number of RE-segments times the spanning-tree count of the segment graph, i.e. the products the compiled equation evaluates on every call. An allosteric mechanism counts both conformations, V×τ of the active one plus V×τ of the inactive one. The default 337 is one above a fully steady-state random-order bi-bi (V×τ = 336), so such a mechanism passes and anything more complex is skipped — equations denser than that are impractical to fit and can blow up derivation/codegen. A one-subunit variant of that bi-bi whose inactive conformation keeps its substrate bindings counts 336 + 16 = 352 and is skipped. Computed from the mechanism graph alone.
  • optional_allosteric_regulators::Vector{Symbol} = Symbol[]: declared allosteric regulators the seed may omit. A reaction that declares regulators seeds the beam fully regulated by default; naming a regulator here lets the beam also start from seeds that do not bind it (added back later by expansion). Listing every declared allosteric regulator restores the unregulated init_mechanisms seed.
  • optional_competitive_inhibitors::Vector{Symbol} = Symbol[]: declared competitive inhibitors the seed may omit, as above.
  • optimizer: Optimization.jl optimizer (required). Recommended: CMAEvolutionStrategyOpt() from OptimizationCMAEvolutionStrategy.
  • n_restarts::Int = 20: multi-start restarts per fit
  • maxtime::Real = 600.0: max time per optimizer run in seconds (common solver option, forwarded to Optimization.solve); each of a fit's n_restarts runs gets it, so a fit can take up to n_restarts × maxtime
  • maxiters::Integer = 10_000_000: max iterations per optimizer run (common solver option, forwarded to Optimization.solve)
  • abstol/reltol/callback = nothing: Optimization.jl common solver options, forwarded to Optimization.solve only when set
  • solver_kwargs::NamedTuple = (;): solver-specific options forwarded verbatim to Optimization.solve (e.g. (; popsize=200) for a CMA-ES solver that supports it); the caller matches its contents to optimizer
  • n_cv_candidates::Int = 5: LOOCV top N candidates with distinct rate-law keys per param count (at least 1)
  • se_threshold::Float64 = 1.0: 1-SE multiplier for model selection. A simpler equation is accepted iff its cv_score is ≤ the best equation's cv_score + se_threshold * cv_score_se. Default 1.0 is the textbook "1-SE rule".
  • save_dir::String = _default_save_dir(): output directory for the search CSVs (initial_mechanisms.csv + equation_search_iteration_N.csv), plus loocv_results.csv (the LOOCV table for every cross-validated candidate) and best_equation.csv (the selected equation and its fitted parameters). Each CSV has an at_bound column: the names, joined by ;, of the constants whose best point lies at a bound of the fit's box (see fit_rate_equation), from the fit on all rows. A save_dir that already holds a .csv file or a progress.log is refused, so the results of two runs never mix.

Beam selection

The beam selects rate-law keys: the mechanisms of one key share one fit (an L phantom's key aside, see below), so a key counts once in the ranks and the budget, and a sweep expands every mechanism it meets of a selected key. A key at parameter count n qualifies for the next-level beam if either:

  • its loss ≤ min(loss_rel_threshold * best(n) + loss_abs_threshold, loss_parsimony_threshold * best(<n)), where best(n) is the lowest loss at parameter count n and best(<n) is the lowest loss over all smaller counts; the second term is dropped at the base count (no smaller level exists yet),
  • OR it falls under the min_beam_width budget: a cumulative per-count allowance that expands at least min_beam_width keys at each count over the whole search, then stops — spent once, not re-granted each time the count is revisited.

A selected key keeps its verdict: a mechanism found later with a key already selected expands. One found later with a key already rejected is judged again and, at the same loss, rejected again, since the cutoff only tightens and a rejection by rank spends the budget. Only an L phantom's key can be rejected and later selected: a member met before the fit of its law at L = 0 is fitted itself and one met after reads that fit, so the key can carry two losses, and a member rejected at one has left the frontier when the other selects the key.

The additive term protects against best_loss approaching zero (simulated / very-low-loss data) where a purely multiplicative threshold would collapse the beam to the single best key.

Model selection (LOOCV)

Every LOOCV candidate gets a cv_score (mean of its per-fold losses) and a cv_score_se (std(fold losses)/sqrt(n_folds)). The best equation is the one with the lowest cv_score; its cutoff is cv_score + se_threshold * cv_score_se. The selected equation is the lowest-cv_score candidate at the smallest n_params that has a candidate at or below the cutoff, so a simpler equation wins whenever it predicts held-out groups as well as the best one to within the best one's fold-to-fold standard error.

A candidate's fold losses come from fitting, on each fold, the mechanism whose fit it reads. An L phantom (L_phantom in the CSVs: a one-subunit variant whose L the data cannot determine) takes its source's fold losses, so beside its source it loses the tie by its extra parameter, and selected without it, it reports L = 0.

EnzymeRates.Derivation.rate_equation — Method
rate_equation(m, concs, params)

Return the net reaction rate of mechanism m at the metabolite concentrations concs and parameters params (both NamedTuples). The rate equation itself is derived from the mechanism's elementary steps by the King–Altman/Cha method: rapid-equilibrium steps collapse to binding constants, steady-state steps are assembled into the King–Altman determinant, and the two combine into the quasi-steady-state flux through the whole mechanism — so one call returns the overall turnover, not the rate of a single step.

params holds the independent constants (parameters(m): the fitted constants, Keq and E_total); the rate law computes each dependent constant from them by its Haldane or Wegscheider relation. Both are read by name, so their fields may come in any order, and fields the law does not read are ignored.

The derivation runs once, at compile time: the body is generated as straight-line arithmetic with no allocations, loops, or matrix operations. Use rate_equation_string to inspect the derived equation symbolically.

EnzymeRates.Derivation.rate_equation_string — Method
rate_equation_string(m; coefficients = false) -> String

Return the rate law of mechanism m as a multi-line String (it returns the text; it does not print). Pass a concrete Mechanism / AllostericMechanism or its compiled EnzymeMechanism singleton.

The text runs as Julia code once params and concs are bound. It destructures parameters(m) from params and the metabolites from concs, lists each dependent constant under # Wegscheider constraints: or # Haldane constraints: as a reference line in Keq and the independent constants, and ends with v = E_total * (Q) * (H) / (D) in the independent constants. H = Π[S] − Π[P]/Keq vanishes at equilibrium; Q and D have positive terms. Numerator and denominator are divided by a normalizer that makes every term of D dimensionless, when one exists: D's constant term when it has one, so D reads 1 + S/K…; otherwise Cleland's normalizer when D holds the terms ΠS/X for every substrate X and ΠS, ΠS the product of the substrates, so each substrate term reads as its concentrations over their Michaelis constants; otherwise a product of powers of D's coefficients with D's unit, each concentration counting as a dimension of its own. When no such product exists, some weighting of the concentrations gives every term of D the same nonzero degree. In E + A <--> E(A), E(A) + B ⇌ E(Q) + P, E(Q) <--> E + Q, for example, the rapid-equilibrium Theorell–Chance step makes every term carry exactly one of B and P. The law then prints as derived, and its terms keep their units. A factor of the normalizer that is not a single term, or an integer to a fractional power, prints once as N = …. An allosteric mechanism prints each conformation's numerator Q_A, Q_I, denominator D_A, D_I, normalizer N_A, N_I, free-enzyme weight F_A, F_I (when they differ) and regulatory-site factor W_A, W_I, then the MWC combination.

With coefficients = true the law reads in named coefficients, v = E_total * n_0 * (H) / (1 + d_S * S + …), each named by the concentrations it multiplies (d_A²_B for A^2 * B). That text runs as Julia code too: it destructures params and concs, prints the coefficient comment, N (N_A, N_I) when the normalizer prints, each coefficient's value in the fitted constants, one line each, for an allosteric law Q_c, D_c and F_c in those coefficients and the site factors W_c, and ends with the v line; the reference lines print only in the full law.

julia> using EnzymeRates

julia> m = @enzyme_mechanism begin
           substrates: S
           products: P
           steps: begin
               E + S ⇌ E(S)
               E(S) <--> E(P)
               E(P) ⇌ E + P
           end
       end;

julia> print(rate_equation_string(m))
(; K_EP_to_E_P, K_ES_to_E_S, k_ES_to_EP, Keq, E_total) = params
(; S, P) = concs
# Haldane constraints:
k_EP_to_ES = K_EP_to_E_P * k_ES_to_EP / (K_ES_to_E_S * Keq)
v = E_total * (k_ES_to_EP / K_ES_to_E_S) * (S - P / Keq) / (1 + S / K_ES_to_E_S + P / K_EP_to_E_P)

julia> print(rate_equation_string(m; coefficients = true))
(; K_EP_to_E_P, K_ES_to_E_S, k_ES_to_EP, Keq, E_total) = params
(; S, P) = concs
# The coefficients are functions of the fitted constants, not parameters:
n_0 = k_ES_to_EP / K_ES_to_E_S
d_S = 1 / K_ES_to_E_S
d_P = 1 / K_EP_to_E_P
v = E_total * n_0 * (S - P / Keq) / (1 + d_S * S + d_P * P)

EnzymeRates.DSL.@allosteric_mechanism — Macro
@allosteric_mechanism begin
    substrates: S, ...
    products: P, ...
    modifiers: I, ...
    allosteric_regulators: X, ...
    catalytic_multiplicity: 2
    steps: begin
        E + S ⇌ E(S) :: EqualAI
        ...
    end
    regulatory_site(2): X::OnlyA, ...
end

Build a two-conformation (MWC) mechanism: the enzyme is active (A) or inactive (I), the free enzyme's inactive-to-active ratio is L, and allosteric regulators bind regulatory sites apart from the catalytic one. The value is an AllostericEnzymeMechanism, the compiled form that rate_equation evaluates without allocating. It prints as the block that builds it, each list sorted, catalytic_multiplicity: written out and one line per kinetic group in canonical order.

It takes the labels and step syntax of @enzyme_mechanism, and:

  • allosteric_regulators: names the metabolites that bind regulatory sites. An allosteric regulator binds only its regulatory site, unless modifiers: lists it too, which lets it bind the catalytic site as well.
  • catalytic_multiplicity: (default 1) is the number of catalytic subunits.
  • regulatory_site(n): X::Tag, Y::Tag is one regulatory site, present n times, and its ligands in any order, each with its tag. Each ligand is an allosteric regulator, and each allosteric regulator sits on exactly one site line.
  • Every statement of steps: ends with its tag: a step after its right-hand side, a parenthesized group after its closing parenthesis, and (step,) :: Tag for a group of one.

A tag says how a statement's constants, or a ligand's binding, differ between the conformations: EqualAI shares one constant, NonequalAI takes one for each (K_A_… and K_I_…), OnlyA acts in the active conformation only and OnlyI in the inactive one only. A catalytic statement takes EqualAI, NonequalAI or OnlyA, or OnlyI when its steps bind only modifiers (modifiers: names or ::Mod copies); a ligand takes any of the four. The conformations interconvert only at free E.

A tagged step's constants vanish in the conformation that lacks it, and the macro rejects a tag set whose limit it cannot show to exist and be unique: an :OnlyA or :OnlyI binding whose two sides the steps that conformation keeps still join; tagged bindings that close a cycle; forms that free E reaches only through tagged steps other than a binding toward them; :OnlyI groups without which the active conformation turns nothing over; a face where the steady state depends on where the enzyme starts; or a face where it cannot show that the limit does not depend on how fast the tagged constants vanish. The checks of @enzyme_mechanism apply as well.

EnzymeRates.DSL.@enzyme_mechanism — Macro
@enzyme_mechanism begin
    substrates: S, ...
    products: P, ...
    modifiers: I, ...
    steps: begin
        E + S ⇌ E(S)
        ...
    end
end

Build a mechanism from its elementary steps. The value is an EnzymeMechanism, the compiled form that rate_equation evaluates without allocating. It prints as the block that builds it, each list sorted and one line per kinetic group in canonical order.

Labels:

  • substrates: and products: (required) name the reactants, without atoms; atoms belong in @enzyme_reaction.
  • modifiers: names the metabolites that bind the enzyme without reacting, such as inhibitors and activators. A substrate or product listed here may bind as a modifier as well.
  • steps: (required) holds the steps in one begin ... end block.
  • substrates:, products: and modifiers: may repeat; their names accumulate. The allosteric labels and step tags belong in @allosteric_mechanism.

Steps, one per line:

  • lhs ⇌ rhs is a rapid-equilibrium step and lhs <--> rhs a steady-state one; either direction may be written.
  • Each side holds one enzyme form and the metabolites the step takes up (left) or gives off (right): E + S ⇌ E(S), E(A) + B <--> E(Q) + P.
  • An enzyme form is a conformation label with its bound metabolites in parentheses: E, E(S), E(A, B). E is the free enzyme; another conformation takes another label, a capital letter followed by lowercase letters and digits such as Estar or F2, never A or I (constant names tag the active and inactive conformations with A_ and I_) and never a metabolite's name. A label such as ES reads as an opaque name and is rejected; write E(S).
  • residual = records the atoms a covalent intermediate keeps, the substrates it took up minus the products it gave off (ping-pong): E(; residual = A - P) is the enzyme without bound metabolites after A bound and P left.
  • A parenthesized tuple of steps is one kinetic group, whose steps share their constants: (E + I ⇌ E(I), E(S) + I ⇌ E(I, S)).
  • A name binds in its own role; a name that is only a modifier is written bare. A substrate or product that modifiers: lists binds as a modifier where it is written X::Mod: E(S) + S::Mod ⇌ E(S, S::Mod).

Every mechanism holds the free enzyme E, with nothing bound and no residual, and its steps join every form to it. Each declared name takes part in some step: a step takes up or gives off each substrate and product, and binds each modifier.

Constants are named after the forms a step joins, each form written as its label and its bound names without a separator: K_ES_to_E_S for E + S ⇌ E(S), k_ES_to_EP and k_EP_to_ES for E(S) <--> E(P). A modifier copy writes Smod, and a residual _res_plusA_minusP.

When the macro's code runs, it rejects a mechanism whose rate law is not defined where data sit, with an error that names the steps at fault: no cycle of steps turns substrates into products; a cycle of rapid-equilibrium steps does, so the rate has no finite value; or, with every product, every substrate, one reactant or every modifier absent, the steady state is not unique or is not the limit the rate law gives as the rapid-equilibrium steps speed up. It also rejects a law with no value there (0/0).

Below, the inhibitor I binds E and E(S) with one constant, and a second S binds E(S) as a modifier, which inhibits at high substrate:

julia> using EnzymeRates

julia> m = @enzyme_mechanism begin
           substrates: S
           products: P
           modifiers: I, S
           steps: begin
               E + S ⇌ E(S)

               E(P) ⇌ E + P
               (E + I ⇌ E(I), E(S) + I ⇌ E(I, S))
               E(S) + S::Mod ⇌ E(S, S::Mod)
           end
       end;

    allosteric_regulators: A, ...
    oligomeric_state: 2
    shared_catalytic_site: (S, P), ...
end

Build the EnzymeReaction that the mechanism search starts from: its reactants with their atoms, and the regulators and oligomeric states the search may use.

  • substrates: and products: (required) list each reactant with its atoms, one chemical formula in brackets: S[C6H12O6]. The atoms of the two sides balance, and a name is a substrate or a product, not both.
  • competitive_inhibitors: lists the competitive inhibitors, names that bind the catalytic site without reacting. A substrate or product listed here may also bind as its modifier copy, which a mechanism writes X::Mod.
  • allosteric_regulators: lists the allosteric regulators, names that bind regulatory sites. A type tag, A::Activator or A::Inhibitor, pins the regulator to the allosteric state that activates or inhibits; an untagged one (:unspecified) may take either. Only these entries take a type tag. A name may be both a competitive inhibitor and an allosteric regulator.
  • oligomeric_state: gives the catalytic multiplicities the search may assign: one positive Int, or a tuple of distinct ones such as (1, 2, 4). It defaults to 1 and is given at most once.
  • shared_catalytic_site: lists (substrate, product) pairs, in either order, that bind one catalytic site, so never both at once.
  • The list labels may repeat; their entries accumulate.

No metabolite is named E_total, Keq, L, N, params, concs or v, or holds _: a rate equation keeps those names, and its constant names join names with _. Nor is one named E, the label of the free enzyme form; a name is an identifier that is no keyword. An enzyme form's name joins its bound metabolites' names without a separator, so the names may not spell one string two ways: with Ac, CoA and AcCoA, E with Ac and CoA bound and E with AcCoA bound would both be EAcCoA. @enzyme_reaction rejects such a reaction and names both spellings (Ac + CoA and AcCoA both spell AcCoA); rename one (Acetyl). A reactant's modifier copy is named Xmod, which counts as a name too.

A reaction prints as the block that builds it, its names sorted:

julia> using EnzymeRates

julia> @enzyme_reaction begin
           substrates: S[C6H12O6], ATP[C10H16N5O13P3]
           products: P[C6H13O9P], ADP[C10H15N5O10P2]
           competitive_inhibitors: P
           allosteric_regulators: A::Activator, I::Inhibitor
           oligomeric_state: (1, 2)
       end

EnzymeRates.Mechanisms.EnzymeReaction — Type
EnzymeReaction

The public concrete reaction descriptor: substrates, products, optional regulators, and the set of catalytic multiplicities the mechanism enumerator is allowed to consider. It is the entry point to the package — pair it with rate data in an IdentifyRateEquationProblem, or pass it to EnzymeRates.Enumeration.init_mechanisms to enumerate candidate mechanisms.

Fields

  • substrates::Vector{Reactant} and products::Vector{Reactant} — each reactant carrying its per-atom inventory (used for ping-pong residual bookkeeping and atom conservation across steps).
  • regulators::Vector{Regulator} — competitive inhibitors and allosteric regulators, each with its kind and effect.
  • allowed_catalytic_multiplicities::Vector{Int} — the oligomeric states, one or more, that the allosteric enumerator may assign to the catalytic core.
  • shared_catalytic_site::Vector{Tuple{Symbol,Symbol}} — (substrate, product) pairs that bind the same catalytic site, and so are never both bound to it at once.

Construct one with the @enzyme_reaction DSL. Each reactant takes an atom bracket (S[C], A[C1H1]); the brackets are load-bearing for ping-pong and multi-substrate reactions. Substrates, products and regulators are sorted by name in the constructor, a name's competitive inhibitor before its allosteric regulator, so two equivalent declarations compare equal under ==/hash. The constructor rejects a name listed as both a substrate and a product: concentrations and constants are keyed by name. For the same reason it rejects a reactant or regulator named E_total, Keq, L, N, params, concs or v, names a rate equation keeps for its constants and the local names of its code, a name holding _, since constant names join names with _, the name E, which labels the free enzyme form, and a name that is no identifier, is a keyword or reads in Julia code as another name (a micro sign as μ), which no DSL text can write. It also rejects names that spell one string two ways, such as Ac, CoA and AcCoA: an enzyme form's name joins the names of the metabolites it binds without a separator, so E with Ac and CoA bound and E with AcCoA bound would share a name. A reaction prints as the @enzyme_reaction block that builds it.

           products:   P[C]

julia> rxn
@enzyme_reaction begin
    substrates: S[C]
    products: P[C]

EnzymeRates.Fitting.FittingProblem — Method
FittingProblem(mechanism::AbstractEnzymeMechanism, table;
    Keq::Real, absolute::Bool = false, reference = nothing)

Construct a FittingProblem from an enzyme mechanism and tabular data.

The table must have columns: group, Rate, and one column per metabolite matching metabolites(mechanism), so no metabolite may be named group or Rate. Uses Tables.columntable for conversion.

With absolute = false (the default) the data are relative: the loss centers each group's log-ratios, which removes each group's scale, so the data fix the rate constants only up to one common factor. reference, optional in this mode, sets that factor: a vector of anchors concentrations => turnover, each a NamedTuple of concentrations in the data's units, where a metabolite left out is zero, and a turnover per unit E_total measured there (a kcat, or a specific activity in turnover units). fit_rate_equation scales the fitted rate constants so the mechanism reproduces the reference turnovers. Without a reference it scales them so the largest absolute rate predicted over the data rows, at E_total = 1, is 1: the rate constants are then in units of the fastest measured condition, not kcats. With absolute = true the data are absolute per-enzyme turnover: the loss is uncentered, the fit is returned unscaled, and passing reference is an error.

Rate values must be finite and nonzero (the loss takes their log; a zero rate gives -Inf), every concentration must be a finite number ≥ 0 (zero is valid), and Keq must be positive and finite. A reference anchor must name metabolites of the mechanism at finite concentrations ≥ 0, with a finite, nonzero turnover.

fp = FittingProblem(m, data; Keq = 2.0, reference = [(A = 10.0, B = 5.0) => 42.0])

We strongly recommend concentrations in M, because Keq values usually assume a 1 M standard state. Other units work as long as all metabolites, Keq and any reference concentrations use the same one. K and k then carry that unit: a K in mM, a second-order k per mM per time. See "Units and the search box" in the Getting Started page for how the fit searches around the concentrations in your data.
