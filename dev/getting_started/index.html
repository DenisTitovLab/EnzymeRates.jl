Getting Started

This page walks through the three pillars of EnzymeRates.jl in one arc: define a mechanism, derive its rate equation, fit it to data, and identify the best mechanism from data automatically. Each section links forward to the full pillar page for details.

Define a reaction and a mechanism

A reaction names the substrates, products, and any regulators. A mechanism adds the elementary steps.

using EnzymeRates

rxn = @enzyme_reaction begin
    substrates: S[C]
    products:   P[C]
end

m = @enzyme_mechanism begin
    substrates: S
    products:   P
    steps: begin
        E + S ⇌ ES
        ES <--> EP
        EP ⇌ E + P
    end
end
@enzyme_mechanism begin
    substrates: S
    products: P
    steps: begin
        E + P ⇌ EP
        E + S ⇌ ES
        ES <--> EP
    end
end

⇌ marks a rapid-equilibrium binding step, described by one equilibrium constant K. <--> marks a steady-state interconversion, described by independent forward and reverse rate constants. E is the free enzyme, and every other name on a side of a step that is not a metabolite names an enzyme form: ES and EP here. The name is yours to choose, but it is part of the constants' names, so a name that says what the form holds keeps the rate law readable. The result is a Mechanism, a plain value: displayed, m prints as the block that builds it, with its lists sorted and its steps in canonical order.

Derive the rate equation

Derivation tutorial and the other deriving pages cover all mechanism forms in depth.

parameters(m)
(:K_EP_to_E_P, :K_ES_to_E_S, :k_ES_to_EP)
metabolites(m)
2-element Vector{Symbol}:
 :S
 :P
print(rate_equation_string(m))
(; K_EP_to_E_P, K_ES_to_E_S, k_ES_to_EP) = params
(; S, P) = concs
# Haldane constraints:
k_EP_to_ES = K_EP_to_E_P * k_ES_to_EP / (K_ES_to_E_S * Keq)
v = (k_ES_to_EP / K_ES_to_E_S) * (S - P / Keq) / (1 + S / K_ES_to_E_S + P / K_EP_to_E_P)
print(rate_equation_string(m; coefficients = true))
(; K_EP_to_E_P, K_ES_to_E_S, k_ES_to_EP) = params
(; S, P) = concs
# The coefficients are functions of the fitted constants, not parameters:
n_0 = k_ES_to_EP / K_ES_to_E_S
d_S = 1 / K_ES_to_E_S
d_P = 1 / K_EP_to_E_P
v = n_0 * (S - P / Keq) / (1 + d_S * S + d_P * P)

rate_equation_string prints the law in its independent constants, each denominator term dimensionless whenever the law has a normalizer (see Normalization); coefficients = true prints it in named coefficients, each defined in the fitted constants before the v line. Both texts run as Julia code once params, concs and Keq are bound. coefficient_values = false (with coefficients = true) leaves the definitions out, which makes the text shorter and easier to read but unable to run. parameters(m) returns the names of the constants a fit estimates. metabolites(m) returns the concentration names the rate equation expects. Keq is the equilibrium constant of the overall reaction — the ratio of product to substrate concentrations once the reaction has reached equilibrium, fixed by the reaction's thermodynamics. It is an input of its own, not a parameter: you always supply it, and the package never estimates it from data.

Evaluate the rate equation numerically

compile_rate_equation(m) compiles the rate equation once into a function. Call it with a NamedTuple of concentrations, a NamedTuple of parameters and Keq:

rate = compile_rate_equation(m)

params = (
    K_ES_to_E_S = 1.0,
    K_EP_to_E_P = 1.0,
    k_ES_to_EP = 10.0,
)
concs = (S = 2.0, P = 0.5)

rate(concs, params, 2.0)
5.0

The rate equation gives the rate per unit enzyme; multiply by the enzyme concentration for an absolute rate. Compile once, outside a loop: the first call derives and compiles the law, and every later call is fast and allocates nothing.

Estimate kinetic parameters from data

Fitting tutorial & data format covers the data format, loss function, and optimizer options in depth.

Generate synthetic data with 5% multiplicative noise from the mechanism above:

using OptimizationCMAEvolutionStrategy, Random
Random.seed!(1)

groups = String[]; Rate = Float64[]; Svals = Float64[]; Pvals = Float64[]
for g in 1:3, _ in 1:8
    s = 0.1 + 9.9 * rand()
    p = 0.1 + 9.9 * rand()
    push!(groups, "G$g")
    push!(Rate, rate((S = s, P = p), params, 2.0) * (1 + 0.05 * randn()))
    push!(Svals, s); push!(Pvals, p)
end
data = (group = groups, Rate = Rate, S = Svals, P = Pvals)
reference = [(S = Svals[1], P = Pvals[1]) => Rate[1]]

fp = FittingProblem(m, data, 2.0; reference)
fitted, loss, retcode = fit_rate_equation(fp, CMAEvolutionStrategyOpt();
                                          n_restarts = 1, maxtime = 2.0)
retcode
:Success

The data table has a group column identifying measurement batches made with one amount of enzyme, a Rate column with measured rates, and one column per metabolite or regulator name (here S and P). Keq, the third argument, is required and always user-supplied. The fit removes each group's arbitrary scale, and reference, a turnover at stated concentrations (here the first data row), sets the scale of the returned rate constants; see Normalized vs absolute rate.

Units and the search box

We strongly recommend concentrations in M, because Keq values usually assume a 1 M standard state. Other units work as long as all metabolites, Keq and any reference concentrations use the same one. K and k then carry that unit: a K in mM, a second-order k per mM per time. The fit searches around the concentrations in your data, so the unit doesn't otherwise change the constants your data determine.

Each constant's search box spans about 6.5 decades either side of a centre taken from the data's concentrations and rates. fit_rate_equation returns at_bound, the names of the constants whose best point lies within 0.01 log units of the box edge. A name in at_bound does not mean the value is wrong: a constant that no data constrain wanders across the box. It means the data do not pin that constant down. Pass the fit_rate_equation keywords lb and ub to widen or narrow the box.

Identify the enzyme mechanism from data

Identify tutorial covers the full rate-equation search, cross-validation, and production settings.

Build an IdentifyRateEquationProblem from the reaction and data, then run identify_rate_equation with the width-1 beam settings so the search finishes in seconds:

prob = IdentifyRateEquationProblem(rxn, data, 2.0; reference)

results = identify_rate_equation(prob;
    min_beam_width = 1,
    loss_rel_threshold = 1.0,
    loss_abs_threshold = 0.0,
    max_param_count = 6,
    n_cv_candidates = 1,
    save_dir = mktempdir(),
    optimizer = CMAEvolutionStrategyOpt(),
    n_restarts = 1, maxtime = 1.0,
    show_progress = false)

print(rate_equation_string(results.best))
(; K_EP_to_E_P, K_ES_to_E_S, k_ES_to_EP) = params
(; S, P) = concs
# Haldane constraints:
k_EP_to_ES = K_EP_to_E_P * k_ES_to_EP / (K_ES_to_E_S * Keq)
v = (k_ES_to_EP / K_ES_to_E_S) * (S - P / Keq) / (1 + S / K_ES_to_E_S + P / K_EP_to_E_P)

The search recovers the mechanism that generated the data: the larger candidates predict held-out groups no better, so the one-standard-error rule keeps the smallest.

min_beam_width=1, loss_rel_threshold=1.0 and loss_abs_threshold=0.0 keep the beam narrow, which makes the search fast and deterministic: at each parameter count the beam admits the lowest-loss rate-law key of the first sweep there, then only a key whose loss is the lowest that count has seen, and every mechanism of an admitted key expands. The full production search uses the wider defaults (min_beam_width=50, loss_rel_threshold=1.3, loss_abs_threshold=0.001, loss_parsimony_threshold=0.99, max_param_count=20, eq_complexity_filter=337) and can run over 100,000 fits, so it usually calls for many cores (see How long a search takes and Running in parallel).

save_dir (by default a new yyyy_mm_dd_results directory under the working directory) must not already hold results. The search writes its progress and results there, ending with loocv_results.csv, the cross-validation table, and best_equation.csv, the selected equation with its fitted parameters; The files in save_dir lists every file.
