2. CORRECTIONS AND GAPS
  G1. Not every step 3 claim matches. The report says JuliaLICM "adds a memset" to the
      hoisted box. In v_loop's IR there is no memset: the box is rooted in a GC frame
      slot at the loop head before its field is first written. A GC inside make() on
      iteration 1 would therefore scan an uninitialized field. That is a second hazard
      from the same hoist. Mention both in the upstream draft.
  G2. Which round aborts. With flushed output the repro passes full GCs 1 and 2 and
      aborts in round 3 (verify_logs/v_loop_r*.log, "GC: 2" at abort). This fits "the box
      becomes old, then gets a young Dict with no barrier". The report's guess of a
      double collection inside one GC.gc(true) is not needed. The GC-level story stays
      inferred; nobody traced it in the GC source.
  G3. Newer 1.12 patch releases are untested. A v1.12.6 tag exists upstream (seen in
      search results); only 1.12.5 is installed. Before filing, check 1.12.6 and nightly,
      since a fix may already exist. I did not install anything.
  G4. Some no-crash rows in the report rest on 1 run (-O0, -O3, --compile=min, which
      was killed after 8 laws). The crash has been deterministic in every crashing
      configuration (0 misses in about 30 runs). The decisive no-crash rows are now
      repeated: -O1, 1.10, no loop, barrier, no Union.
  G5. Scan coverage. As the report says, the scan covers only code these workloads
      compile. It does not cover other optimizers, the CV grid at scale, or the DSL
      macros.

3. ON THE PHASE 3 RECOMMENDATION
  Agreed: proceed. The EnzymeMechanism{Sig} type-parameter encoding is not involved,
  and deserialization on workers carries no extra risk. Watch the phase 3 Mechanism
  design for the hazard: a loop that reads, from a Union of types (for example
  Union{Mechanism, AllostericMechanism}), a field whose type differs across the members
  and is an immutable struct holding references. Reading such a field forces a fresh
  box in the loop. A field of the same concrete type in both members, or a heap
  object (Vector, Dict, mutable struct), is safe. If phase 3 adds a CI remark guard,
  it must run with --pkgimages=no (C7).
