# P6 report: a graph-based mechanism type

## Question

Can a graph-based `Mechanism` (Denis's item 8) meet all of these?

- built in microseconds;
- plain field equality;
- steps whose written direction does not matter;
- no `EnzymeReaction` field;
- still usable by enumeration.

The pass criterion has four parts: microsecond construction, zero false merges, every equivalent variant equal, and hashes that are stable across processes.

### The type, `GM.GMech`

| Field | Contents |
|---|---|
| `substrates`, `products` | Sorted `Symbol` lists |
| `mets` | Sorted metabolite table of `Met(name, inh)`; `inh` marks a competitive-inhibitor binding, so `A` and `A::Inh` are separate entries |
| `confs` | Sorted conformation table |
| `forms` | `Vector{Form}`, sorted by content. A `Form` is isbits: packed bound counts and residual counts (`UInt128`, 4 bits per table entry) plus a conformation index |
| `edges` | `Vector{Edge}`, isbits `(a, b, cons, rel, re)`, sorted |
| `group` | One kinetic-group label per edge, numbered by each group's first edge |
| `tags` | One allosteric tag per group; empty means a plain mechanism |
| `multiplicity`, `sites` | Catalytic multiplicity, and regulatory sites as a sorted multiset |
| `cache` | Lazy `Ref` holding the analyses; excluded from `==`, `hash` and serialization |

- **Derived, not stored:** inhibitors, regulators and `metabolites`.
- **Equality and hashing:** `==` and `hash` compare fields and are defined explicitly for every struct.
- **Storage rule:** an edge is stored with `a < b`, except that a binding-like edge is stored taking its metabolite up.
- **Physical-forward direction:** `orient(m)` derives it as a separate `Vector{Bool}` for naming and priority. It is a faithful port of today's tiers, with tier 3 either by rendered name (`tier3 = :name`) or by form index (`tier3 = :index`).

## Results

The population is all 2799 mechanisms of the shared data (806 plain, 1993 allosteric; 20,576 steps). Timings are medians of 11 batches on aarch64 with Julia 1.12.5. The package was re-measured under the same protocol from mechanisms rebuilt from the export; all 2799 rebuilds store exactly the exported structure.

### Faithfulness to the package

These checks compare GM with the exported data; every one shows 0 failures.

- **Round trip:** every exported mechanism converts to GM and back without loss.
- **Names:** every rendered form name equals the package's.
- **Content:** groups, tags, the metabolite, inhibitor and regulator lists, and the plain-binding test all match. There are 17,380 plain bindings.
- **Inactive mask:** it reproduces the package's pruning (`inactive_kept`) in all 1993 allosteric mechanisms.
- **Orientation:** the ported tiers reproduce the package's stored direction on all 20,576 steps.
  - Steps decided by tier 0, 1, 2 and 3: 18,638, 1,933, 1 and 4.
  - All tier-3 steps are in three handwritten mechanisms (16, 22, 24).
  - Tier 3 by form index gives the same direction as by name on all of them.
  - No kinetic group has two tied steps, so `_orient_tied_steps` changes nothing here.
- **Analyses against the package's own, 0 mismatches in 2799:**
  - RE segments and per-form exponent extras, compared with `_re_segment_extras`;
  - the cycle space, compared by rank against `_thermodynamic_constraints`;
  - the Haldane multiple of each cycle;
  - the 276 RE cycles counted by `re_cycle_closure`.
- **DSL fixtures:** all 42 `MECHANISM_TEST_SPECS`, lowered from the test source text by `DslLower`, equal the exported specs, and none equals another spec.
- **Printer round trip:** printing all 2799 mechanisms as DSL text, parsing and lowering them gives equal values for all 2799.

## Verdict

**PASS.** Construction takes about 1 µs (3.7 µs at most over the populations). There are zero false merges and zero false splits against the package's own partition. All 16,794 equivalent variants are equal with equal hashes, and all hashes match across two processes.

Caveats:
- No enumeration move was ported. I showed the child constructions and analyses that moves read, not move logic.
- The package's allosteric constructor includes the `:OnlyA` feasibility check, which GM does not run. So the fair allosteric comparison is the canonical-form-only figure (14×), not 55×.
- The data exercises inhibitor copies only in the specs and handwritten mechanisms (at most 6 table entries), plus 2354 `inh` mutations.

## Design implications

1. **The type.** Content-sorted forms, isbits edges, per-edge group labels, tags per group, sorted sites, and no `EnzymeReaction`.
   - One type covers plain and allosteric mechanisms.
   - Inhibitors, regulators and `metabolites` are derived.
   - Without the reaction field, a graph that sits on two reactions is one value. Here that merges 237 classes that `init_bibi` and `init_bibi_pp` differ in only by atoms.
2. **Identity is content; names only render.**
   - Write `==` and `hash` explicitly for every struct; never rely on the default struct hash.
   - The hash is for in-process deduplication only, because it depends on the Julia version. A key written to disk needs canonical text plus an explicit digest.
3. **Store edges by rule 1.** It is enough for equality, hashing, enumeration and the analyses. A pure `a < b` rule would store only 22 bindings (all fused) as releases; the take-up exception keeps `is_binding` a one-sided test.
   - Compute physical-forward direction for naming, the priority order of the solve, group alignment and the printer. The printer needs it because rule-1 storage prints `E(P) <--> E(S)`.
   - Use tier 3 by form index, which removes rendered strings from orientation.
   - Keep the group tie rule. It never fires in the populations, but hand-written groups of conformation changes need it.
4. **Split validation.**
   - The constructor checks structure only: no self-loops, no metabolite on both sides, each reaction once, uniform groups (up to direction, one RE flag), well-formed tags and sites, residual roles.
   - These become predicates at the DSL and public boundary or in enumeration pre-filters: bottomless segment, `:OnlyA` feasibility, atom conservation, rendered-name collision, and role-changing bindings (`E + P::Inh → E(P)`, which GM currently accepts).
5. **Compute the analyses on demand and drop the `cache` field.** At 0.9 µs they cost nothing next to a derivation. The cache adds 780 B, a custom serializer and mutable state.
   - Fundamental cycles of a spanning forest replace the `Rational{BigInt}` nullspace.
   - Subgraphs such as the inactive state become edge masks. Nothing is re-canonicalized, so names and orientation come from the full graph only. Today's rebuild changes inactive-state names in 115 mechanisms (Known issue 1); no step was re-oriented in this data.
6. **Enumeration.**
   - RE flips, splits and tag changes keep every form and edge index. Edge order does not depend on the RE flag.
   - A child that adds a form or metabolite re-indexes everything, because the table and form order shift. Moves must not carry parent indices into such children.
7. **Sig.** Turn the fields into tuples and decode by `collect`.
   - One `EnzymeMechanism{Sig}` for plain and allosteric mechanisms.
   - `AllostericEnzymeMechanism` and its lifts go away.
8. **`types.jl`: from 746 to about 460 code lines.** The mechanism part, excluding `EnzymeReaction` (about 140, unchanged), goes from about 600 to about 320.
   - **Unnecessary:**
     - the metabolite type hierarchy as mechanism content, `Residual`, `_met_sort_key`;
     - `Species`, `_species_name`, `_show_fields`, `_adds_metabolite`, `_binds_ligand`;
     - `Step` and its accessors, `bound_metabolite`, `_is_chemistry`;
     - all of Canonical Step Form: `_canonical_step_direction`, `_reversed`, `_orient_tied_steps`, `_canonicalize_step_directions`, `_canonical_groups`;
     - the string sort keys: `_met_names`, `_step_canonical_key`, `_regulatory_site_canonical_key`;
     - `_assert_uniform_groups` and `_assert_each_reaction_once` (replaced by 6 integer lines);
     - `_forms`, `_flat_steps`, `_NamingCache` with its plumbing, `Mechanism`, `AllostericMechanism`, `_AnyMech`, `_with`;
     - the Sig codec: `_to_sig`×4, `_sig_of`, `_SIG_METABOLITE_TYPES`, `_mechanism_from_sig` (replaced by about 14 lines);
     - `AllostericEnzymeMechanism` with its lifts, `_concrete`, and one `show` method.
   - **Moved:** the tiers go to naming as `orient` (about 35 lines). `_assert_distinct_form_names` goes to naming, because `E(NAD, P)` and `E(NADP)` stay distinct forms by content but both render `ENADP`. `_re_segment_extras` and `_bottomless_re_segment` go to a graph-analysis file (about 110 lines), which also takes over the cycle and inactive-state code in `thermodynamic_constr_for_rate_eq_derivation.jl` and `rate_eq_derivation.jl`.
9. **DSL lowering.** Each steps line becomes one group. A trailing `:: Tag` sets `tags[g]`; it is peeled from the right side's last term or applied to a parenthesized group.
   - Each side splits on `+` into exactly one form. `Conf(m…; residual = A - P)` becomes a `RawForm`; `X` becomes `Met(X, X ∉ reactants)`; `X::Inh` becomes `Met(X, true)`.
   - `⇌`/`<-->` set the RE flag; the written direction is irrelevant. A site line becomes a `Site`.
   - The macro emits `GMech(subs, prods, steps, labels; tags, multiplicity, sites)`. There is no placeholder reaction.
   - The prototype is 92 lines. With error messages and the macro wrapper, production is about 150, plus the printer at about 25.
10. **Production estimate** for what P6 prototypes, about 545 lines in all:

    | Piece | Lines |
    |---|---|
    | Type, constructor, accessors, children and Sig | ~250 |
    | Orientation | ~35 |
    | Analyses | ~110 |
    | Mechanism DSL lowering | ~150 |

## Open questions for Denis

1. **Metabolite cap.** The encoding caps a mechanism at 32 distinct metabolite entries (name and role) and 15 copies of one metabolite per form or side, with an error beyond that. The populations use at most 6; ter-ter with every reactant copy needs about 14. Is the cap acceptable, or should we pay for a general encoding? I did not measure that alternative.
2. **Tier 3 by form index instead of rendered name.** The results are identical on all 2799 mechanisms. A name could flip direction only for a hand-written isomerization whose tiers 1 and 2 tie and whose content order differs from its name order. Is that acceptable?
3. **Colliding rendered names** (`E(NAD, P)` against `E(NADP)`). Keep rejecting them at naming, as today and as I recommend? Or render names with a separator, which renames every constant?

## Surprises and failures

- Almost none of the orientation machinery is exercised. Tiers 2 and 3 decide 5 of 20,576 steps, and the group tie rule decides none.
- The package's inactive-state rebuild re-oriented no steps in this data. Its 115 name changes come from a different group representative on the pruned graph.
- A struct defined in `Main` happened to hash identically across processes. Only the runtime-module control exposed the problem, so a test using only `Main` types would have missed it.
- The Sig is not smaller than today's. The gain is in decoding without canonicalization.
- The constructor costs about 160 ns per edge, mostly from sorting two keys per step. Decoding is 3× the constructor because it allocates per form; that matters only if dead-end-style moves become a hot path.
- One mistake: my first name-collision demo used `P::Inh`, which renders `Pinh`, so it showed no collision. I fixed and reran it.
- No Julia process is left running.
